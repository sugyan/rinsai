# rinsai — decision log

What was decided, why, and — where the decision is conditional — what would have to be measured to revisit it. [DESIGN.md](./DESIGN.md) is the plan, [CLAUDE.md](./CLAUDE.md) is the rules, [CONVENTIONS.md](./CONVENTIONS.md) is what is frozen. Where the work stands is `gh issue list` and `git log`.

**One decision, one entry, and an entry has two states.**

- **Live** — the code has not frozen it yet. Four things and nothing else: what was decided; what was rejected and the reason it lost; the condition that would reopen it; a pointer to CONVENTIONS.md for the rule. A measurement the decision rests on is written here, once, and nowhere else.
- **Retired** — CONVENTIONS.md now carries the rule and the code is built on it. The entry collapses **in place** to a line: date, decision, the rejected alternatives *by name*, the condition, the pointers. Retiring is done by the pull request that freezes the convention, not by a later tidy-up that never comes.

**Conclusions are superseded, never revised.** Retirement removes reasoning; it may not change, soften or reverse a conclusion, and a conclusion that turned out wrong keeps its date and gains a superseding entry beneath it. That is what append-only was protecting — a log editable towards hindsight is worth nothing — and it survives retirement intact. A copied measurement may always be replaced by its pointer: two copies of a number drift, and this log has already done it once.

**What is not an entry, however true.** How a finding was found, which review pass caught it, what an earlier draft said, the order two things happened in, a restatement of what the code does. That is the pull request's, and `git log` is the index.

⚠️ **The exception worth its bytes: an expectation that measurement refuted.** It stays live indefinitely — the prediction, the measured contradiction, a pointer to the table — because losing one costs somebody the experiment again. The *narrative* of how a refutation was found is not exempt.

- **2026-08-07 — Review of E0 step 2, and the one rule it changed: a measurement does not go in a doc comment.**
  - **No defect was found in the search itself**, and the things worth not re-deriving next time are these. The **root's returned value is exact**: β is `INFINITE` so the root never fails high, and its children enter with α at `-INFINITE` so they never fail low — which is what makes the early break on `score.is_mate()` a break on a proof rather than on a guess, for a loss as much as for a win. **`pv[0]` can only ever be assembled from exact children**, because a child that fails high scores at most α at the parent and so never reaches `update_pv`. That last induction has one step that looks like a counterexample and is worth stating, because it is where re-deriving it goes wrong: a child that fails **low** *does* reach `update_pv` at its parent — it hands the parent a score at or above β — but doing so cuts the parent, so that parent is itself fail-high and its line never lands on a published one. The truncated lines exist; none of them surface.
  - **A number handed over by a reviewer is trusted twice over** — once because it arrived inside a careful audit, once because someone else appears to have done the work. Neither is a reason: re-derive it, or attribute it, and the attribution is not a substitute. What re-deriving it also showed is the calibration DESIGN.md §8's quiet-machine precondition rests on: **node counts reproduce to the digit across runs and times do not** — noise cannot move a node count and can invent a time.
  - **`negamax_root` cannot tell a fail-low from an abandoned iteration, and E1's aspiration windows are what will find that out.** It returns `None` on "no root move raised α", which coincides with "no root move finished" only while α starts at `-INFINITE`; `Window::open`'s doc nonetheless advertised that the method already takes the window as a parameter so that aspiration search could narrow it. It cannot: a fail-low would return `None` and `Searcher::search` would break out of the deepening loop instead of re-searching — **no wrong answer announced, no panic, and no failing test**, because every test here searches an open window. A `debug_assert` now pins the contract and the doc names what E1 owes the method.
  - **Time on the clock is not time on the wire.** `movetime`/`byoyomi` are honoured to the last millisecond, with nothing reserved for delivering the move; the network delay margin is step 5's and stays there. The operating consequence is in CONVENTIONS.md, because floodgate turns a byoyomi overrun into an immediate loss.
- **2026-08-07 — E0 step 3 becomes 3a and 3b, and quiescence lands. Three frozen conventions retired, and two of the step's own claims refuted by measurement.**
  - **A change that rebaselines every committed node count lands alone.** Quiescence and the table are not one change: landing them apart makes each node-count delta attributable, which matters more here than anywhere else because DESIGN.md §8's loop does not exist yet and node counts are the only instrument E0 has.
  - **Quiescence counts checked plies, not plies — and the first implementation got that wrong.** A single cap on total quiescence depth looks obviously right and is not: swept on the drop-heavy middlegame at depth 4, a cap tight enough to save nodes fired its floor on a fifth of all quiescence nodes, which is a cap cutting *capture chains* off in the middle, i.e. the horizon effect reintroduced two plies down and paid for at full price (the sweep is below). The two kinds of ply are not alike: a capture chain is self-limiting, because every capture moves a piece off the board and quiescence plays no drops, so occupancy strictly decreases; a check-evasion chain has no such argument, an evasion need not be a capture, and an evasion list is *every* legal move including drops. **The generalisation: a bound is only sound if it is a bound on the thing that is actually unbounded.**
  - **Two results from choosing that bound's value that nobody would have predicted from argument.** Allowing *zero* checked plies is not a cheap approximation but an incorrect engine — it evaluates while in check and misses a mate one ply away, reporting material. And the node count is **not monotone in the bound**: allowing two checked plies costs about a third of what allowing one costs, because resolving a check returns a score the search above can cut on while refusing to resolve it returns a number that defeats pruning for the rest of the tree. "Search less, spend less" is not safe anywhere near a check. Two is the measured minimum and is correct; E1 owns it thereafter.
  - **`DEFAULT_DEPTH`'s evenness rule is retired with its reason.** It existed because an odd depth ended the line on a capture nobody answers, which is precisely what quiescence removes. The value stays at four; the assertion is deleted rather than left to pin a rule that no longer has an argument behind it.
  - **Two claims carried into the plan from reading rather than measuring, both false.** That the initial position offers a capture one ply in — `7g7f` opens *Black's* bishop diagonal, not White's, since White's own pawn on 3c blocks 2b — so its depth-1 node count is still exactly `1 + N` and the node-counting test keeps the fixture. And that a depth-1 iteration with quiescence "runs to tens of thousands of nodes in a tactical position", which is true of roughly one position in a few thousand and of no fixture in this repository. Both were written down as premises for tests, and both would have produced tests that pass for the wrong reason.

- **2026-08-10 — The USI layer is not shared with `tuishogi`, because an engine and a GUI need opposite halves of the protocol.**
  - **What the question turns on, and it is not how the code is factored.** USI is asymmetric: an engine **reads** what a GUI sends and **writes** its answers, and a GUI does exactly the reverse. The function that parses `go btime 1000` and the function that writes it are two functions, and having either does not give you the other. rinsai holds the engine half and only that, so an extraction hands `tuishogi` nothing it can call.
  - **So this was never "extract the USI layer"**, but "write a new crate holding both directions of both types, and retire part of the existing one into it". **A shared type is the *union* of both sides' needs rather than the intersection** — rinsai's deliberately lossy `GuiCommand` variants are each small and together a permanent tax on both consumers, paid so that neither can have the type it wants.
  - **The GUI half is on crates.io, and rinsai cannot use it — the same fact from the other side.** `usi` 0.6.2 (nozaq/usi-rs) is MIT, depends on `itertools` and `thiserror` and nothing else, and **does not depend on `shogi_core` at all** — its moves are strings. It offers `EngineCommand::parse`, `Info(Vec<InfoParams>)` and `BestMoveParams { MakeMove, Resign, Win }`, the last carrying 入玉宣言, which is the shogi-specific thing a chess-derived codec would be missing. Its `GuiCommand` can be written but not read, and reading it is the half an engine needs.
  - **The same asymmetry re-justifies `rinsai-protocol`, which DESIGN.md §4 had resting on the wrong thing.** Rejected: splitting it on "the line-oriented loop the CSA client would share with USI" — that loop is a few lines of framing, and CSA shares nothing else, not the grammar, not the move notation (`+7776FU` against `7g7f`), not the state machine. What the two protocols genuinely share is the layer *underneath*: the same `SearchDriver`, `Game` and time management, and the same "one answer per turn, structurally" invariant. That is a session layer, not a codec, and the crate stays reserved for E2.
  - **Reopened when** a dialect bug found in one repository turns out to have a twin in the other, or a second Rust consumer of either half appears.
- **2026-08-10 — WebAssembly compatibility is kept as a constraint on the search core, and nothing is built for it.**
  - **Three runtime traps, and the roadmap already owns the code around all three.** `thread::Builder::spawn` in `SearchDriver`; `Instant::now` at the **top of `NegamaxSearcher::search`**, which reads the clock unconditionally rather than only inside `Budget`, because the `info` line carries `time` and `nps` on every iteration; and `Condvar::wait` behind `wait_until_signalled`. Step 5 rewrites `Budget` for real time management and wants an injectable clock for its own tests regardless — a wall clock is not something a time-management SPRT can be written against — so **the clock is step 5's work rather than a separate task**; E2 rewrites `SearchDriver` for Lazy SMP; doing either seam early means writing it twice. The third is not a trap to fix but a subset to declare: `go infinite` and `go ponder` cannot work on one thread, so a browser session implements less than USI and says so.
  - ⚠️ **A trap located by reading the type that owns the concept will miss the caller that reads it for another reason.** The clock trap was found by reading `Budget`, the only place a *deadline* lives; the unconditional `Instant::now()` one scope up was never checked, and it is what makes `go depth 6 nodes 3000000` panic on wasm before it searches a node.
  - **`catch_unwind` is inert there, and that is worth knowing before it is relied on.** The target is `panic = "abort"`, so the two nested catches in the worker catch nothing and the "a panicking search answers `resign` and the engine plays on" guarantee is a **native-only** property. The workspace profile's note about deliberately not setting `panic = "abort"` is true of the builds it describes and does not travel.
  - **`web-time` was checked and not adopted.** It is `MIT OR Apache-2.0` and a genuine drop-in for `Instant`, but on wasm it pulls `js-sys` and `wasm-bindgen` and their trees into a lock file whose whole third-party set is three crates, every one of them provenance-scan surface. A `cfg`-selected clock adds none. **Adopted if** a browser build ever needs a deadline *inside* the engine that the host cannot express as depth or nodes.
  - **The honest ceiling, stated so it is not rediscovered at E3.** The E3 network's feature transformer alone is far larger than a browser download can be — 125 388 × 256 × int16 is 61 MiB against the ~2.6 MB a playable browser engine ships in — and halving it would not change the conclusion, so **the constraint is download size, not arithmetic** and compression is not the lever. Neither is GPU offload, and WebGPU is additionally the wrong instrument for *this* evaluation: NNUE's cost is an incremental accumulator update of a few columns, αβ evaluates positions strictly sequentially so there is nothing to batch, and a dispatch costs more than the whole evaluation. GPU is the right instrument for the E6 DL/MCTS branch and not for this one. So the browser build's **evaluation** forks from the native one — a fork the native design already has, since `EvalFile` exists precisely because networks are swapped without recompiling.
  - **Three E3 consequences that are free now and expensive later**, recorded here because E3 is where they land: the network's feature-set dimension belongs in the file header rather than a `const`, or a smaller net needs a second inference path forever; `EvalFile` should be a thin wrapper over a `load_network(&[u8])`, which a browser needs, self-play wants, and a filesystem path cannot provide; and every SIMD backend keeps a scalar reference implementation, which E3 needs anyway to test the SIMD against and which is what keeps a build without NEON or AVX2 possible at all.
  - **Revisited when** the browser stops being of interest, or when honouring the CONVENTIONS.md rule costs measurable Elo natively. In that case the native engine wins and the wasm build is dropped — it is a constraint accepted while it is free, not a goal with a claim on the roadmap.
- **2026-08-10 — E0 step 3b: the transposition table. Two predictions of this project's own refuted by measurement, and one pre-existing test found hollowed out by the change that hollowed it.**
  - **The ordering is the half that pays.** Searching the stored move first is worth between 1.00× and **14.02×** across five fixtures and four depths, super-linearly in depth. **The scores are worth the rest.** That is the concrete content of the 2026-08-06 decision that moved TT move ordering out of E1 — an argument then, a number now.
  - **Capping quiescence by *checks* rather than by plies, and the cost is not monotone in the cap.** A total-ply cap cuts capture chains mid-way, which is the horizon effect two plies further down — at a cap of 4 the floor fired on 22% of quiescence nodes. Counting checks instead, on the drop-heavy fixture at depth 4: 0 checks costs 30.8 M nodes **and is wrong** (it evaluates while in check and misses a mate one ply away), 1 costs 22.1 M, **2 costs 7.0 M**, 4 costs 7.7 M. ⚠️ **Two checked plies cost a third of what one costs** — resolving a check returns a score the search above can cut on, so "search less, spend less" is not safe near a check. `QS_MAX_CHECK_PLIES = 2` is the measured minimum that is also correct; E1's item 9 owns revisiting it with an SPRT.
  - **An in-window `Exact` cut was predicted to truncate the published line. It does not.** The reasoning was sound as far as it went: a table cut returns after `pv[ply].clear()` and before the move loop, so the node's line is empty while its parent raises alpha without cutting. Measured, letting the `Bound::Exact` arm cut unconditionally leaves every published line **byte-identical** over three fixtures at depths one to eight, moving only the node count and by at most 1.2%. The restriction is kept anyway — the path is reachable, the argument is about soundness rather than performance, and 1% is what it costs — and what covers the rule is a unit test on the rule itself. ⚠️ **An end-to-end test of a rule about an internal seam is a test of whether that seam is on today's hot path**, which is a different question and a less stable one.
  - **"Unpromised" is precisely the property no assertion about today's layout can test.** `Entry`'s doc forbids storing a `Move` because `Move` carries no `#[repr]` and its size is therefore unpromised; the sixteen-byte test stayed green under that mutation, because `Option<Move>` happens to fit the same sixteen bytes on today's compiler. Neither the rule nor the test was wrong; the note joining them was. The limit applies again the moment E1 or E3 adds a packed struct.
  - **Quiescence does not probe the table, and the reason that was about to be written down is false.** The conventional expectation — quiescence is 91–99% of all nodes, so probing there thrashes the table and evicts the interior entries that pay — is **refuted on every row**: patching it in halves the tree at roughly flat wall-clock — 0.77× on the initial position, 0.50× and 0.47× on a drop-heavy middlegame. Not shipped at 3b on three grounds about the step rather than the feature: it is a separable search change and this project runs one at a time; the instrument that could say whether halving the tree makes the engine stronger is SPRT, which did not exist yet; and it would rebaseline the counts `bench` exists to freeze, in the same commit that freezes them. **Recorded with its number so E1 inherits a measurement rather than an expectation**, and because the expectation is what would otherwise have been recorded as the reason and believed.
  - **`each_iteration_starts_from_the_last_answer` rests on a fixture measured to disagree with shunsai's generation order**, and this step took that discrimination away at the initial position by adding the table. It moved to the one fixture of five still measured to disagree, and it asserts the disagreement *before* the assertion that depends on it, so the next time a change takes the discrimination away the test says so rather than going quiet.
  - **`bench`'s per-position counts live in the source, which is the one place a number is *duplicated* on purpose.** A regression baseline has to be executable to be a regression test, and a copy of it in a document is a second copy that drifts — the failure the rule exists to prevent, arriving by the other route.
  - ⚠️ **Allocating the advertised default table costs about as much as a whole E0-depth search** — 6–21 ms for 256 MiB against 13–20 ms for a depth-6 search from the initial position. Harmless where it is, because it happens once per searcher and `isready` is allowed to take arbitrarily long — but a future change that moved the allocation onto the `go` path would look free.
- **2026-08-11 — A unit test on a helper does not cover the helper's callers, and an advertised maximum is a promise about behaviour.**
  - **A sabotage note's mutation has to be made at the site the note is attached to.** Step 3b's mate-score ply adjustment had no coverage at all: deleting the `to_table` call from `store`, or the `from_table` call from `probe`, left the entire suite green — `bench` included — because the unit test exercised the two free functions directly and never went through `Table`. The rule this repository already had (the mutation must be made and the test must go red) was followed, for the *function*. CONVENTIONS.md carries the narrowed rule.
  - **An advertised maximum is a promise about behaviour, not only about parsing.** `USI_Hash` declared `max 65536`, which reaches a 64 GiB `vec!` — infallible, so a refusal aborts the process from the worker thread, mid-tournament, on a value the engine itself offered. What made it easy to miss is that the bound had been checked against the *spec* and never against the machine. CONVENTIONS.md carries the fallible-allocation rule.
  - **Grep a diff for its own step number and check each thing an earlier step promised that step would do.** Three of the four prose defects in this review were forward promises written by an earlier step and left unchecked when the step they named arrived. The question is cheap and repeatable.
- **2026-08-11 — E0 step 4: 千日手 and 連続王手. Two of this step's own predictions refuted.**
  - **The rule is implemented at four occurrences, and the two-fold cut most engines use is deferred to E1 with its condition.** Scoring the *first* repetition on the search path as a draw is standard practice and it prunes cycles, but it is a **search heuristic** rather than the rule: 千日手 is four occurrences and nothing less. There is no instrument for strength during E0, so the deviation would be adopted on argument, which CLAUDE.md §3 forbids. It goes to E1, where one feature is one SPRT. **The consequence worth stating, because it shapes every test in the step**: twelve plies is more than an E0 search sees, so at these depths the fourth occurrence is reached almost entirely out of the *game's* history rather than from inside the tree — a fixture that can exercise this has to carry a real move list, and a bare `sfen` root cannot test repetition at all.
  - **A 連続王手の千日手 win gets a band of its own rather than the mate band.** Rejected: reporting it as `score mate N`, which would announce a mate whose principal variation does not deliver one — what `a_reported_mate_is_a_real_mate` exists to forbid. The three bands, the `clamp_to_eval` retarget and the flatness are in CONVENTIONS.md.
  - **⚠️ The prediction that `bench` would need re-freezing was wrong, and it could not have been right.** Every count is identical to the digit and the total is unchanged. The reason is the four-occurrences rule above: the seven committed positions carry histories one to seven plies long, and a depth-4 search cannot reach a fourth occurrence from any of them — so **`bench` cannot exercise repetition at all, and is not a guard for it**. 
  - **⚠️ The prediction that mate-in-4 and mate-in-5 would be out of reach was also wrong, and by two orders of magnitude.** The plan reasoned from branching — nine plies of full-width search with only transposition-move ordering — and concluded the deep rows would not fit in `cargo test`. Measured, the whole ladder costs under six milliseconds in the *dev* profile, mate-in-5 at depth 9 taking 18 924 nodes — because the mate is found several iterations before the depth that nominally contains it. The arithmetic was not wrong about full-width search; it was wrong about the position, because a forced mating sequence is exactly the input alpha-beta prunes best. **A cost predicted from branching alone is a claim, not a finding** — and the cheap way to find out was to build the fixture and search it, which took less time than the estimate did.
  - **The known imprecision this leaves is stated rather than fixed.** The unbuilt fix — propagating a "this subtree saw a repetition" flag up and declining to store — is a separable search change with a node-count cost and no instrument at E0 to weigh it. Every engine lives with the imprecision; CONVENTIONS.md states it. Revisited when E1 item 11 puts quiescence in the table, or when E2's Lazy SMP shares one.
  - ⚠️ **A no-op mutation reports GREEN and is indistinguishable from a false note**, so a sweep that does not check its own mutations manufactures exactly the finding it exists to detect. Two of this step's fifty-nine changed the source text without changing behaviour — one replaced `DEFAULT_HASH_MB` with the literal it already equals, the other only added a comment. Verify that a mutation changed behaviour, not only text.
  - **`Game::clone`'s Zobrist cross-check stays a `debug_assert`.** The concern is real: the history's keys come from shunsai's *incremental* key, so a drift would corrupt a repetition verdict directly rather than merely the SFEN record. What settles it the other way is the cost of the alternative — `Game::clone` runs on the **protocol thread**, once per `go`, so a real assertion puts a panic there, and `usi.rs` opens by promising that bad input never stops the loop. Trading a quiet wrong verdict for a dead engine is not a trade this project's error policy makes. Meanwhile the check does run on every `Game::clone` under `cargo test`. **Revisited if** an incremental-key drift is ever actually observed, or when E2's CSA client starts using the record for an in-game decision.
  - **`Engine::go`'s `submit`-failed branch is defensive and untested, and is named here rather than left to be discovered.** When `submit` returns `false` the protocol layer answers `bestmove resign` itself. `SearchDriver` has a unit test that `submit` reports the failure; the *protocol* half has none, because reaching it needs a worker that is gone while the loop still runs. Kept because it guards the one-answer-per-`go` invariant, untested for the same reason.
- **2026-08-12 — Step size is set by the oracle, not the phase. E0's remaining sub-steps land as two pull requests, harness first; one-feature-one-SPRT is scoped to strength patches; E1 goes machine-serial.**
  - **The line that decides where each working style is right: what instrument can see the work's failure.** Neither candidate is adopted whole — not building the engine end-to-end and verifying afterwards, and not the one-sub-step-one-PR pacing practised so far, whose price was about a week and whose safety margin turned out to be already spent — the sole remaining silent-statistical failure on the E0 list, repetition against the transposition table, was not in the batch. Where a deterministic suite can see a failure — scenario, conformance, parity, `bench` — work batches. Where only paired games can, it does not, whatever the implementation speed: a 20-Elo regression crashes nothing, plays legal shogi, and is invisible at any sample a person watches; bundle N such changes and attribution is destroyed at merge time, because unbundling costs more games than measuring the N separately would have.
  - **What changed is review capacity; the statistics of paired games did not.** The felt slowness was measured, and its cause is ritual volume rather than the size of the code steps: across fourteen sessions a third of all Edit/Write operations targeted `.md` files, and two of the six `main` commits since code existed were substantively prose-only. The sub-step boundaries buy reviewable diffs and isolated risk, not measurement.
  - **"Accept some bugs" is adopted with its noun corrected: accept weakness, never incorrectness.** No move ordering, no pruning and a naive time allowance are weakness — E1's job, earned patch by patch under SPRT. A wrong 千日手 verdict, a flag fall or an illegal move is incorrectness: it loses whole games and is cheap to pin with a scenario test. And this log is why "plausible, unmeasured, fix it later" stays banned near the search: the quiescence cap's shape, the check-plies floor, its non-monotone cost, the qsearch-probing expectation, the Exact-cut hazard and the ordering fixture were each written down as expectation and each refuted when measured.
  - **The sabotage re-run narrows to the files a diff touches, with full-tree sweeps at phase gates**, because a global rule is quadratic in project age and would have strangled the E1 queue. CONVENTIONS.md carries the rule.
  - **The price of batching is a retroactive audit.** The harness's first act is a **non-regression SPRT of the finished E0 against the step-3b engine** (elo0=−5, elo1=0): whatever the batch hid, that is the instrument that looks for it afterwards. It is tracked as an issue.
  - **Accepted risk, stated.** Scenario suites are this record's weakest instrument — a test that could not fail has been found at every step so far. The two rituals with a demonstrated hit rate stay mandatory everywhere: the sabotage made at the site for any new test of a silent failure, and the claim-by-claim reading pass for protocol surfaces and for TT/repetition semantics. What a batch pull request drops is the rest of the per-step ritual, not those.
- **2026-08-12 — The match harness is own Rust code in `crates/xtask`; Ayane is not vendored. The referee is `crates/rinsai-game`, moved from tuishogi and publication-intended.**
  - **Rejected: vendoring Ayane**, read at `yaneurao/Ayane@5fc6afd`, which lacks all three things the gates need. **No fixed-node play** — `set_time_setting` accepts nine time tokens and nothing else (`source/shogi/Ayane.py:1056-1068`), and the `go` line it builds is always clock-shaped. **No 千日手 adjudication** — its own comment says a repetition draw is expected to leave via max_moves (`Ayane.py:1221-1222`, cap 320 where floodgate plays 512). **No legality checking** — a `bestmove` is string-concatenated onto the position (`Ayane.py:1215`) and `GameResult.ILLEGAL_MOVE` is declared (`Ayane.py:925`) but never assigned. Patching in nodes support and wrapping an external repetition referee around it would leave Ayane contributing process-spawning — which `usi_process.rs` already does in-tree — at the price of a second toolchain in the measurement loop. CLAUDE.md §2's permission to vendor it stays true and stays unused.
  - **The referee had already been written twice, and the second copy was the better referee.** tuishogi's rules layer — legality-gated `play`, undo, 詰み/千日手/連続王手 adjudication over an exact position index — moved into this workspace as `crates/rinsai-game` (tuishogi @ 73d0d9c, MIT, same author, relicensed by the author to `MIT OR Apache-2.0`). Rejected: a sibling repository, because a path dependency carries **no unreleased-dependency debt** — the shunsai git pin is the one such debt E0's exit criterion exists to clear, and the harness must not add a second; and vendoring into `xtask`, because a crate boundary is what lets tuishogi adopt it. Publication is deferred until the API has a second consumer in hand.
  - **Two implementations of the repetition rule now exist by design.** The search keeps its own — zobrist-filtered, integrated with the search path — and the referee runs `rinsai-game`'s normalised-SFEN, exact one. They were held to agree by differential tests before the harness played a game: over refereed games, which end at the fourth occurrence, the two windows provably coincide; on a *fifth* occurrence they deliberately differ, because `rinsai-game` cannot represent one. The duplication buys the property the harness wanted anyway — **the referee's legality library is `shogi_legality_lite`, not shunsai**, so every refereed game is a differential test of the players' movegen rather than an echo of it. Its first field data: the openings pipeline replayed every qualifying floodgate game through `rinsai-game`, and shunsai accepted every candidate line — no disagreement in either direction.
- **2026-08-12 — A batch pull request needs a review pass that reads for defects, because its own gates are built to pass.** ⚠️ The steps 6+7 batch cleared every gate set for it, and a review afterwards found fifteen defects, thirteen confirmed by running the failure rather than by reading. **None of them could have failed a gate.**
  - **The pattern, stated so the next batch can look for it.** Two of the classes this project already knows: rules whose remaining guard was lost while moving a layer between repositories — coverage separated from code — and false claims in prose. The new one is the middle class. Defects in the harness's own decision path (the verdict, the stopping bounds, the opening validation, the log's identity, the seat attribution) all produce a plausible number rather than a crash, which is the failure shape CLAUDE.md §3 says only paired games can see — **except that these corrupt the paired games themselves. A defect in the measuring instrument is invisible to that instrument.** 
  - **What that says about the batch rule.** The pacing entry above scoped batching to work a deterministic suite can see fail; that was right and is unchanged. What this adds is that **a suite the same batch wrote is not that instrument for the batch that wrote it.** Both mandatory rituals operate on what was written rather than on what was omitted, so **a batch's review has to ask what is missing, not only whether what is present is true.**
  - **Not adopted: a rule that every moved test must be diffed against its origin.** It is the obvious lesson and it is too narrow — the same class arrives whenever coverage and code are separated, and a rule keyed to repository moves would not have caught the untested `position` string, which was never anywhere else. What generalises is the question, not the procedure.
- **2026-08-12 — `openings-v2`: a candidate is judged on an iteration that finished.**

- **2026-08-13 — Step 5a: the harness cuts the wait at the mover's allowance, and the delivery margin stays the engine's.**
  - **Decided.** A flag fall *is* the wait ending without an answer, not a comparison made afterwards: the referee reads the answer, and only silence under a clock flags. An answer that arrived is played however much of the allowance it took, and the elapsed the seat reports is measured to the instant the line arrived, so it can never exceed the bound the wait was cut at.
  - **Rejected: judging the flag on `elapsed >= allowance`.** It was the first shape, and it decides the boundary on the harness's own work: the elapsed then included the stale-line drain, both writes and the `bestmove` parse, so an answer delivered inside the allowance could still be charged past it and the legal move discarded. Reproduced at 300 µs of margin in 1 243 of 2 000 trials. It also routed every engine failure through the clock — a crash or a nonsense line arriving late became a flag fall, which is *not* abnormal, so the run lost both its ⚠️ tally and the stderr post-mortem.
  - **Rejected: waiting under the hang timeout and comparing elapsed afterwards.** The timeout would have to be set above the whole clock it is watching — and the overrun it would have to clear is the quantity being measured. A detector tuned against its own subject is not one. It also keeps the misreport the step exists to remove: a badly overrunning engine hits the hang timeout first and is recorded as `Timeout`, i.e. a degraded run rather than a lost game.
  - **Rejected: a grace window before the flag falls.** ⚠️ **Measured, and this is why the temptation is strong: rinsai overruns every byoyomi it uses, by a constant ~0.14 ms** — the poll interval, not the depth-1 iteration, and independent of the byoyomi from 1 ms to 1000 ms. A grace wide enough to absorb that is a gate scoring itself, and the overrun is already paid for correctly: it comes off the main time, which is what a main time is for. Consequence worth knowing before setting one up: **a clocked run with no main time flags on ply 1 at every byoyomi**, by construction rather than by fault. The engine-side margin is #16's.
  - **`--concurrency > 1` under a clock warns rather than refuses.** Refusing would also block the deliberately non-authoritative smoke run; the warning is printed, put in the summary and recorded as `noisy` in the log, so a run cannot later be read as a measurement it was not.

## Recorded but deliberately not built

[CLAUDE.md](./CLAUDE.md) forbids building for a consumer that does not exist
yet, and requires recording the condition instead. These are those records —
subject-ordered rather than dated, because each is a standing condition rather
than a moment.

- **The named-caller rule's one exception: a type that exists to freeze a
  convention.** `score.rs` shipped in step 1 with no caller, because a wrong
  negamax sign, centipawn scale, mate band or `MAX_PLY` is a class of bug SPRT
  reads as "that patch was bad". Of the six surfaces it put on probation, five
  carry a named caller and stayed; **`Score::NONE`'s did not turn up, and it
  went at step 3b.** The rule is in [CONVENTIONS.md](./CONVENTIONS.md).
  ⚠️ **A named caller that does not turn up is a result too.** `MAX_PLY`'s doc
  predicted per-ply state would gain a static evaluation at step 3; quiescence
  computes its stand-pat as a local and nothing reads it again, so per-ply
  state is still exactly the principal variation. The `Stack` struct is
  deferred to E1 — killers or futility, whichever lands first — and its trigger
  is written as **the first *second* field** rather than as a step number,
  because a step number is what went stale.
- **The move buffer: three rejected shapes.** `ArrayVec<Move, 593>` per ply on
  the stack — same size but *per node*, and `Move` has no `Default`, so an
  `unsafe`-free version needs `MaybeUninit`, which the workspace denies.
  `Vec<Move>` per ply — one malloc/free per node. A ply-indexed array in the
  search stack, where E3's accumulator stack goes — it leaves the move list
  borrowed while recursing on `&mut stack`.
- **`[patch.crates-io]` for an unpublished crate — checked, and rejected
  anyway.** It **does** work (cargo's own
  `tests/testsuite/patch.rs::nonexistent`). Rejected on three grounds: the
  manifest's `shunsai = "0.1"` would assert something false; `[patch]` is
  honoured only at the workspace root, so `rinsai-search/Cargo.toml` would stop
  saying where shunsai comes from; and it would keep overriding silently after
  publication, so the switch we are trying not to forget would never go red.
- **A `quit` watchdog — not needed, and constrained if it ever is.** It has to
  be a **bounded wait** in `shutdown` rather than a `process::exit`: an
  unconditional exit would make a hung in-process conformance test *pass*.
- **`quit` stops the search**, and `usi::run` reads input as fast as it arrives,
  so `printf … | rinsai` answers from the depth-1 iteration. ⚠️ **A conformance
  dialogue cannot exercise a search of a stated size** — that belongs in
  `rinsai-search`'s own tests or in `usi_process.rs` over real pipes.
- **Threads, not async — and no `tokio`.** Rejected: an async runtime for one
  stdin reader and one CPU-bound search, which `spawn_blocking` puts back on a
  thread anyway, for a dependency in a tree that is provenance-scan surface
  (CLAUDE.md §2). **Reopens if** something inside the engine process has to wait
  on *many* independent I/O sources at once; E2's Lazy SMP, E2's single CSA
  connection and E3's in-process self-play are not that.
- **A browser build: the constraint is built, the build is not.** No web
  application asks for one, so what lands is CONVENTIONS.md's Portability rule
  and a CI step keeping the target compiling — a `cfg(target_arch = "wasm32")`
  branch nobody exercises rots faster than an absent one. Rejected in the shape
  it would take: a **threaded** build, which costs nightly (`-Z build-std`,
  `+atomics`) and COOP/COEP on the host to optimise the weakest build for
  strength, and a **typed JS API** in place of `step(line) -> Vec<String>`,
  which would re-encode `usi/command.rs` and `info.rs` into a second protocol
  covered by one set of tests. The runtime traps are in the 2026-08-10 entry
  above.
