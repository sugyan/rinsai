# rinsai — decision log

What was decided, why, and — where the decision is conditional — what would have to be measured to revisit it. [DESIGN.md](./DESIGN.md) is the plan, [CLAUDE.md](./CLAUDE.md) is the rules, [CONVENTIONS.md](./CONVENTIONS.md) is what is frozen. Where the work stands is `gh issue list` and `git log`.

**One decision, one entry, and an entry has two states.**

- **Live** — the code has not frozen it yet. What was decided; what was rejected and why it lost; the condition that would reopen it.
- **Retired** — CONVENTIONS.md carries the rule and the code is built on it. The entry collapses **in place** to a line: date, decision, the rejected alternatives *by name*, the condition. Retiring is done by the pull request that freezes the convention. A retired entry keeps whatever the exemption below protects, and nothing else.

**Conclusions are superseded, never revised.** Retirement removes reasoning; it may not change, soften or reverse a conclusion, and a conclusion that turned out wrong keeps its date and gains a superseding entry beneath it.

⚠️ **The one thing that stays live indefinitely: an expectation that measurement refuted** — the prediction, the measured contradiction, and the numbers. Losing one costs somebody the experiment again.

- **2026-08-07 — Review of E0 step 2, and the one rule it changed: a measurement does not go in a doc comment.**
  - **No defect was found in the search itself**, and the thing worth not re-deriving is this. The **root's returned value is exact**: β is `INFINITE` so the root never fails high, and its children enter with α at `-INFINITE` so they never fail low — which is what makes the early break on `score.is_mate()` a break on a proof rather than a guess. **`pv[0]` can only ever be assembled from exact children.** ⚠️ That induction has one step that looks like a counterexample: a child that fails **low** *does* reach `update_pv` at its parent — it hands the parent a score at or above β — but doing so cuts the parent, so that parent is itself fail-high and its line never lands on a published one. The truncated lines exist; none of them surface.
  - **A number handed over by a reviewer is trusted twice over** — once because it arrived inside a careful audit, once because someone else appears to have done the work. Neither is a reason: re-derive it, or attribute it. What re-deriving it also showed is the calibration the quiet-machine precondition rests on: **node counts reproduce to the digit across runs and times do not** — noise cannot move a node count and can invent a time.
  - **`negamax_root` cannot tell a fail-low from an abandoned iteration, and E1's aspiration windows are what will find that out.** It returns `None` on "no root move raised α", which coincides with "no root move finished" only while α starts at `-INFINITE`. A narrowed window would return `None` on a fail-low and `Searcher::search` would break out of the deepening loop instead of re-searching — **no wrong answer announced, no panic, and no failing test**, because every test here searches an open window. A `debug_assert` pins the contract.

- **2026-08-07 — E0 step 3 becomes 3a and 3b, and quiescence lands.**
  - **A change that rebaselines every committed node count lands alone.** Quiescence and the table are not one change: landing them apart makes each node-count delta attributable, which matters more here than anywhere else because the measurement loop does not exist yet and node counts are E0's only instrument.
  - **Quiescence counts checked plies, not plies — and the first implementation got that wrong.** The two kinds of ply are not alike: a capture chain is self-limiting, because every capture moves a piece off the board and quiescence plays no drops, so occupancy strictly decreases; a check-evasion chain has no such argument, an evasion need not be a capture, and an evasion list is *every* legal move including drops. **The generalisation: a bound is only sound if it is a bound on the thing that is actually unbounded.** The sweep that chose the value is in the step 3b entry.
  - **`DEFAULT_DEPTH`'s evenness rule is retired with its reason.** It existed because an odd depth ended the line on a capture nobody answers, which is precisely what quiescence removes. The value stays at four; the assertion is deleted rather than left to pin a rule with no argument behind it.

And that a depth-1 iteration with quiescence "runs to tens of thousands of nodes in a tactical position", which is true of roughly one position in a few thousand and of no fixture here. Both were premises for tests, and both would have produced tests that pass for the wrong reason.

- **2026-08-10 — The USI layer is not shared with `tuishogi`, because an engine and a GUI need opposite halves of the protocol.**
  - **What the question turns on, and it is not how the code is factored.** USI is asymmetric: an engine **reads** what a GUI sends and **writes** its answers, and a GUI does exactly the reverse. The function that parses `go btime 1000` and the function that writes it are two functions, and having either does not give you the other. rinsai holds the engine half and only that, so an extraction hands `tuishogi` nothing it can call.
  - **So this was never "extract the USI layer"**, but "write a new crate holding both directions of both types". **A shared type is the *union* of both sides' needs rather than the intersection** — rinsai's deliberately lossy `GuiCommand` variants are each small and together a permanent tax on both consumers.
  - **The GUI half is on crates.io, and rinsai cannot use it — the same fact from the other side.** `usi` 0.6.2 (nozaq/usi-rs) is MIT and **does not depend on `shogi_core` at all** — its moves are strings. It offers `EngineCommand::parse`, `Info` and `BestMoveParams { MakeMove, Resign, Win }`, the last carrying 入玉宣言. Its `GuiCommand` can be written but not read, and reading it is the half an engine needs.
  - **The same asymmetry re-justifies `rinsai-protocol`.** Rejected: splitting it on "the line-oriented loop the CSA client would share with USI" — that loop is a few lines of framing, and CSA shares nothing else, not the grammar, not the move notation (`+7776FU` against `7g7f`), not the state machine. What the two protocols genuinely share is the layer *underneath*: the same `SearchDriver`, `Game` and time management, and "one answer per turn, structurally". That is a session layer, not a codec, and the crate stays reserved for E2.
  - **Reopened when** a dialect bug found in one repository turns out to have a twin in the other, or a second Rust consumer of either half appears.

Neither is GPU offload, and WebGPU is additionally the wrong instrument for *this* evaluation: NNUE's cost is an incremental accumulator update of a few columns, αβ evaluates positions strictly sequentially so there is nothing to batch, and a dispatch costs more than the whole evaluation. So the browser build's **evaluation** forks from the native one — a fork the native design already has, since `EvalFile` exists precisely because networks are swapped without recompiling. That is the concrete content of the 2026-08-06 decision that moved TT move ordering out of E1 — an argument then, a number now.

- **2026-08-11 — E0 step 4: 千日手 and 連続王手.** *Retired: CONVENTIONS.md's search and score-band rules carry it.* Rejected: reporting a 連続王手 win as `score mate N`, which would announce a mate whose principal variation does not deliver one.

- **2026-08-12 — Step size is set by the oracle, not the phase.**
  - **The line that decides where each working style is right: what instrument can see the work's failure.** Where a deterministic suite can see a failure — scenario, conformance, parity, `bench` — work batches. Where only paired games can, it does not, whatever the implementation speed: a 20-Elo regression crashes nothing, plays legal shogi, and is invisible at any sample a person watches; bundle N such changes and attribution is destroyed at merge time, because unbundling costs more games than measuring the N separately would have. *CLAUDE.md carries the resulting rule.*
  - **What changed is review capacity; the statistics of paired games did not.** The felt slowness was measured, and its cause is ritual volume rather than the size of the code steps: across fourteen sessions a third of all Edit/Write operations targeted `.md` files, and two of the six `main` commits since code existed were substantively prose-only.
  - **"Accept some bugs" is adopted with its noun corrected: accept weakness, never incorrectness.** No move ordering, no pruning and a naive time allowance are weakness — E1's job, earned patch by patch under SPRT. A wrong 千日手 verdict, a flag fall or an illegal move is incorrectness: it loses whole games and is cheap to pin with a scenario test. And this log is why "plausible, unmeasured, fix it later" stays banned near the search: the quiescence cap's shape, the check-plies floor, its non-monotone cost, the qsearch-probing expectation, the Exact-cut hazard and the ordering fixture were each written down as expectation and each refuted when measured.
  - **The price of batching is a retroactive audit, and it came back clean.** The harness's first act was a **non-regression SPRT of the finished E0 against the step-3b engine** (elo0=−5, elo1=0): whatever the batch hid, that was the instrument that looked for it afterwards. Run 2026-08-19 at `--nodes 1000000` over `openings-v3.sfen`, one opening per pair and no replication: **H1 accepted**, 697 pairs / 1394 games, W-D-L 487-428-479, pentanomial `[7, 35, 599, 55, 1]`, LLR +2.967, score 50.29% (elo +2.0 est), zero abnormal games. ⚠️ **The first attempt was invalid and is why `openings-v3` exists** — it played more pairs than `openings-v2` had openings, so the sample replicated.
  - **Accepted risk, stated.** Scenario suites are this record's weakest instrument — a test that could not fail has been found at every step so far. The two rituals with a demonstrated hit rate stay mandatory: the sabotage made at the site for any new test of a silent failure, and the claim-by-claim reading pass for protocol surfaces and for TT/repetition semantics.

Rejected: a sibling repository, because a path dependency carries **no unreleased-dependency debt**, and the harness must not add a second; and vendoring into `xtask`, because a crate boundary is what lets tuishogi adopt it.
  - **Two implementations of the repetition rule now exist by design.** The search keeps its own — zobrist-filtered, integrated with the search path — and the referee runs `rinsai-game`'s normalised-SFEN, exact one. They were held to agree by differential tests before the harness played a game: over refereed games, which end at the fourth occurrence, the two windows provably coincide; on a *fifth* occurrence they deliberately differ, because `rinsai-game` cannot represent one. The duplication buys the property the harness wanted anyway — **the referee's legality library is `shogi_legality_lite`, not shunsai**, so every refereed game is a differential test of the players' movegen rather than an echo of it.
- **2026-08-12 — A batch pull request needs a review pass that reads for defects, because its own gates are built to pass.** ⚠️ The steps 6+7 batch cleared every gate set for it, and a review afterwards found fifteen defects, thirteen confirmed by running the failure rather than by reading. **None of them could have failed a gate.**
  - **The pattern, stated so the next batch can look for it.** Defects in the harness's own decision path (the verdict, the stopping bounds, the opening validation, the log's identity, the seat attribution) all produce a plausible number rather than a crash — the failure shape only paired games can see, **except that these corrupt the paired games themselves. A defect in the measuring instrument is invisible to that instrument.**
  - **What that says about the batch rule.** Batching is scoped to work a deterministic suite can see fail; that is unchanged. What this adds is that **a suite the same batch wrote is not that instrument for the batch that wrote it.** Both mandatory rituals operate on what was written rather than on what was omitted, so **a batch's review has to ask what is missing, not only whether what is present is true.**
  - **Not adopted: a rule that every moved test must be diffed against its origin.** It is the obvious lesson and it is too narrow — the same class arrives whenever coverage and code are separated, and a rule keyed to repository moves would not have caught the untested `position` string, which was never anywhere else. What generalises is the question, not the procedure.
- **2026-08-12 — `openings-v2`: a candidate is judged on an iteration that finished.** *Retired: CONVENTIONS.md carries the rule; the engine signal is `completed_depth` on `BestMove::Play`.* v1 read the partial line, whose score is the best over a *prefix* of the root list — 150 of its 256 lines were selected that way.
  - **Rejected: "drop a candidate whose balance search hit the cap"**, this file's own parked proposal. It keys on tree size — only positions whose depth-6 search fits the cap survive — and the open, capture-rich middlegames that removes are where E1's ordering and pruning are meant to pay, so the set would measure those patches on the positions least able to show them.
  - ⚠️ **"A lower bound admits what a completed search rejects, and never the reverse" was false**, and stood from steps 6+7 through two reviews: the window is two-sided, so a lower bound errs both ways, and the reverse direction is the one that moved four of the eight lines.
  - **Reopens if** the balance search stops being a rinsai search, or the window stops being two-sided.
- **2026-08-13 — Step 5a: the harness cuts the wait at the mover's allowance, and the delivery margin stays the engine's.**
  - **Decided.** A flag fall *is* the wait ending without an answer, not a comparison made afterwards: the referee reads the answer, and only silence under a clock flags. An answer that arrived is played however much of the allowance it took, and the elapsed the seat reports is measured to the instant the line arrived, so it can never exceed the bound the wait was cut at.
  - **Rejected: judging the flag on `elapsed >= allowance`.** It decides the boundary on the harness's own work: the elapsed then included the stale-line drain, both writes and the `bestmove` parse, so an answer delivered inside the allowance could still be charged past it and the legal move discarded. Reproduced at 300 µs of margin in 1 243 of 2 000 trials. It also routed every engine failure through the clock — a crash or a nonsense line arriving late became a flag fall, which is *not* abnormal, so the run lost both its ⚠️ tally and the stderr post-mortem.
  - **Rejected: waiting under the hang timeout and comparing elapsed afterwards.** The timeout would have to be set above the whole clock it is watching — and the overrun it would have to clear is the quantity being measured. A detector tuned against its own subject is not one.
  - **Rejected: a grace window before the flag falls.** ⚠️ Measured, and this is why the temptation is strong: rinsai overran every byoyomi it used, by a constant ~0.14 ms — the poll interval, independent of the byoyomi from 1 ms to 1000 ms. A grace wide enough to absorb that is a gate scoring itself. ⚠️ **The measurement is superseded 2026-08-14 by step 5b**, which gives the engine a delivery margin so it finishes inside the byoyomi. The grace window stays rejected on its other argument.
  - **`--concurrency > 1` under a clock warns rather than refuses.** Refusing would also block the deliberately non-authoritative smoke run; the warning is printed, put in the summary and recorded as `noisy` in the log, so a run cannot later be read as a measurement it was not.
  - **Reopens if** the harness ever has to stand in for a server that grants a delivery margin of its own.
- **2026-08-14 — E0's exit criterion is met: the dependency is `shunsai = "0.1"` from crates.io.**
  - ⚠️ **The predicted re-baseline did not happen, and this is the entry that keeps somebody from doing the experiment again.** The exit-criterion issue expected the bump to move every `bench` count, on the ground that shunsai's generation order is unspecified and the release was several commits and two measured speedups ahead of the pin. Measured at depth 4 and 16 MiB: all seven counts unchanged. The openings pipeline's fixture reproduces byte for byte as well. **A count depends on the order and the membership of the generated list**, and a faster way to reach the same list moves neither.
  - **Rejected: `Game::search_board` rebuilding the board from the record.** What the rebuild bought was an empty undo stack, so a search unwinding past its own root met `undo_move`'s `expect` rather than a position nobody described. 0.1.0 has no stack and no such `expect`, and the guarantee is now structural. What replaced the rebuild is a copy of the game's own board, on a ground the rebuild never had: the search seeds its repetition path from entries taken from that board, so a second board agreeing only by assertion is two lineages compared against each other. ⚠️ **The `expect` was also the only check on the searcher's do/undo balance**; `negamax` and `qsearch` each carry a `debug_assert` on the node's key in its place.
- **2026-08-14 — Step 5b: the allowance is byoyomi-shaped, the clock is a trait returning `Duration`, and `DeliveryMargin` is an operator setting.** *Retired: CONVENTIONS.md carries the rules and what pins them.*
  - **Rejected: the chess-shaped `remaining / divisor + increment`.** A referee grants the byoyomi period afresh each move and charges main time only with the excess, so the period is free. That formula answers `btime 0 byoyomi 10000` — a long game's ordinary endgame — with an instant move and ten unused seconds.
  - **Rejected: `Clock::now` returning `Instant`.** `Instant` has no public constructor, so such a trait can only be implemented by something that calls `Instant::now` — the one thing the seam exists to make optional.
  - **Rejected: `Budget<'a, C>` carrying the clock.** Built in `search` from `&self.clock`, it holds a shared borrow of `*self` across a deepening loop that needs `&mut *self` — E0502, escapable only by `C: Clone` and a clone per search.
  - **Rejected: tuning `DeliveryMargin` by SPRT.** Its right value is a property of the deployment, and self-play on one quiet machine drives it to zero — the answer that loses games over a network.
  - ⚠️ **Rejected after adopting it and reverting: taking the margin off the spend, `spend.min(available) - margin`.** The argument for it is good enough to be made again — inside the cap the margin does nothing while main time remains, which reads as a bug. Both forms uphold `allowance ≤ available - margin`; the outside form additionally surrenders the margin on every move, and measured, a 900 ms clock at the default margin then gave an allowance of zero and stopped the engine at depth 1.
  - **Reopens if** a referee ever grants the engine a delivery margin of its own, or if byoyomi stops being granted afresh per move.
- **2026-08-18 — `rinsai-game`'s `Outcome` carries the five endings a refereed engine game reaches, and each is set by a method of its own rather than by a door taking an `Outcome`.**
  - **Decided**: 時間切れ, 反則負け (carrying the `IllegalMoveKind`), 入玉宣言, 最大手数 and 対局放棄 join the four the crate had. Asked for by the second consumer (#28); the argument that they belong here is that both consumers need the same set, and this repository already modelled it twice.
  - **Rejected: a public setter taking an `Outcome`.** It hands a caller the three endings `play` *derives* — 詰み, 千日手, 連続王手の千日手 — and a caller that sets one of those asserts what the crate exists to check. Six small methods buy the property that a declared ending and a derived one cannot be spelled the same way.
  - **Rejected: a second enum for the declared endings, converted into `Outcome`.** Two vocabularies and a conversion, where both consumers match on `Outcome` at the end of it anyway.
  - **`EndReason` is not collapsed onto `Outcome`, though #28 raises the question.** The harness keeps `Died`, `Protocol` and `Timeout` apart because the run summary tallies them apart; `Outcome::Abandoned` is one variant for all three, so the collapse would delete what a degraded run prints about itself. **Reopens if** the summary stops needing the three apart, or `Outcome` grows the distinction.
  - ⚠️ **A consumer that only `Display`s an `Outcome` compiles clean against a new variant** and renders a sentence nobody chose; `#[non_exhaustive]` does not help, because the hazard is the absent `match` rather than an exhaustive one. Nothing here can fix that for a downstream.
- **2026-08-19 — a generated set's history is traced by a tag on the rev its header names.** *Retired: CONVENTIONS.md carries the rule.*
  - **Rejected: relying on the branch surviving**, which is what had been holding v1 and v2 together without anybody deciding it. This repository has never made a merge commit, so a set's generating rev is never on `main`; the two older revs were reachable only because their branches were never deleted, and nothing said they had to be.
  - ⚠️ **Rejected after measuring, and the expectation was the reverse:** using *the commit that added the file* as the handle, on the argument that it is on `main` and its tree must contain the generator. It does not. Review commits land between generating a set and merging it, so the adding commit carries a **later** generator — measured, `openings.rs` differs by 83 lines for v1 and 9 for v2 between the two. A handle that is easy to reach and wrong is worse than the rev.
  - **Reopens if** the sets stop being generated from a rev-stamped header, or if tags stop being pushed with the artefact.
- **2026-08-19 — the prose machinery is dropped, and no artifact cites a repository document.**
  - **Decided.** rinsai carries `.claude/settings.json` with permissions and nothing else — no plugin, no hook, no reviewer agent, no command — so a checkout is all a session needs. The prose rules survive as six imperatives in CLAUDE.md, one of them new: **never reference a repository document from an artifact.** 73 such references were removed from source, manifests, frozen sets and CI, and CI's `FILE.md §N` citation guard went with them.
  - **The record the decision rests on.** The `prose-reviewer` loop ran ten passes on the openings-v3 branch and **five changed no executable line at all**; one sentence was rewritten three times and was still false at pass 6, where the defect turned out to be in `first_timed_mover` rather than in the comment. `/create-pr` step 2 said "fix the sentences and return to step 1", which has no stopping condition. Against that, the mechanical checker found nothing on the tree it was run over.
  - **Rejected: moving the plugin into the repository** as `.claude/hooks` + `.claude/agents`, which is what tuishogi does and would have worked in the cloud. The machinery was the cost, not its location.
  - **Rejected: publishing the marketplace to GitHub** and referencing it from project settings. It keeps one shared copy for three repositories, and keeps the loop.
  - ⚠️ **Rejected on measurement, twice over: `--concurrency 2` as the stated default.** A draft of CLAUDE.md said engine matches default to it; `runner.rs` defaults to 1. The rule is an upper bound an operator obeys, not a description of the code — **a rule written as a claim about code is a claim, and this one was false the day it was written.**
  - **Reopens if** false claims start reaching `main` again at a rate the six imperatives do not hold down.

## Recorded but deliberately not built

[CLAUDE.md](./CLAUDE.md) forbids building for a consumer that does not exist
yet. These are the records that replace the code — subject-ordered rather than
dated, because each is a standing condition rather than a moment.

- **The named-caller rule's one exception: a type that exists to freeze a
  convention.** `score.rs` shipped in step 1 with no caller, because a wrong
  negamax sign, centipawn scale, mate band or `MAX_PLY` is a class of bug SPRT
  reads as "that patch was bad". Of the six surfaces it put on probation, five
  carry a named caller and stayed; **`Score::NONE`'s did not turn up, and it
  went at step 3b.**
  ⚠️ **A named caller that does not turn up is a result too.** `MAX_PLY`'s doc
  predicted per-ply state would gain a static evaluation at step 3; quiescence
  computes its stand-pat as a local and nothing reads it again, so per-ply
  state is still exactly the principal variation. The `Stack` struct is
  deferred to E1 — killers or futility, whichever lands first — and its trigger
  is written as **the first *second* field** rather than as a step number,
  because a step number is what went stale.
- **The move buffer: three rejected shapes.** `ArrayVec<Move, 593>` per ply on
  the stack — same size but *per node*, and `Move` has no `Default`, so an
  `unsafe`-free version needs `MaybeUninit`, which the workspace denies.
  `Vec<Move>` per ply — one malloc/free per node. A ply-indexed array in the
  search stack, where E3's accumulator stack goes — it leaves the move list
  borrowed while recursing on `&mut stack`.
- **`[patch.crates-io]` for an unpublished crate — checked, and rejected
  anyway.** It **does** work (cargo's own
  `tests/testsuite/patch.rs::nonexistent`). Rejected on three grounds: the
  manifest's `shunsai = "0.1"` would assert something false; `[patch]` is
  honoured only at the workspace root, so `rinsai-search/Cargo.toml` would stop
  saying where shunsai comes from; and it would keep overriding silently after
  publication, so the switch we are trying not to forget would never go red.
- **A `quit` watchdog — not needed, and constrained if it ever is.** It has to
  be a **bounded wait** in `shutdown` rather than a `process::exit`: an
  unconditional exit would make a hung in-process conformance test *pass*.
- **`quit` stops the search**, and `usi::run` reads input as fast as it arrives,
  so `printf … | rinsai` answers from the depth-1 iteration. ⚠️ **A conformance
  dialogue cannot exercise a search of a stated size** — that belongs in
  `rinsai-search`'s own tests or in `usi_process.rs` over real pipes.
- **Threads, not async — and no `tokio`.** Rejected: an async runtime for one
  stdin reader and one CPU-bound search, which `spawn_blocking` puts back on a
  thread anyway, for a dependency in a tree that is provenance-scan surface.
  **Reopens if** something inside the engine process has to wait on *many*
  independent I/O sources at once; E2's Lazy SMP, E2's single CSA connection and
  E3's in-process self-play are not that.
- **A browser build: the constraint is built, the build is not.** No web
  application asks for one, so what lands is CONVENTIONS.md's Portability rule
  and a CI step keeping the target compiling — a `cfg(target_arch = "wasm32")`
  branch nobody exercises rots faster than an absent one. The runtime traps and
  the rejected shapes are in the 2026-08-10 entry above.
